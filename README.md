# kanachin-app-collection

## Web版ランキングの方針

- 公開データと公式APIを利用し、取得できる数値を表示する。
- Web版専用のリアルタイムチャット監視基盤・AI実行環境は導入しない。
- Kickの同時視聴者数、同じ放送の視聴者増減、順位変動、配信時間を維持する。
- 録画アプリ側のチャット監視・AI機能には変更を加えない。
- ニコ生・Kickとも上位10件のみ表示。表示中の10秒更新を基本とする。
- 参考：既存サイトのランキング仕様。番組単位の公開サムネイル・統計を活用し、未取得データは推測しない。
- 旧ChatGPT Sites版の表示仕様を参考に、順位変動と前回比をCloudflare版で再実装。旧サイトのiframe・API・画像URLには依存しない。
- `/embed/rankings` は同一Workerの独立ランキング表示用ルート。公開データの取得先は引き続き必要。
- ニコ生アクティブ人数は、公開カードで直近10分の人数が確認できる場合のみ表示する。チャット監視・AI実行環境は導入しない。
- 添付 live-ranking-source.zip（worker/index.mjs）のランキングHTML解析と公式RSS画像取得を移植。勢いランキングの公開データを追加し、ニコ生の勢いptと来場者数は別々に扱う。独自チャット監視・D1依存・旧サイトAPIは移植しない。
- r20: 公開視聴ページの番組IDと配信情報WebSocket URLを検証し、統計イベント（adPoints/giftPoints）を不足時のみ短時間受信する。1回の更新につき最大3番組、番組別キャッシュ120秒。コメントサーバー・映像取得・常時接続・ログインは行わず、取得失敗時に数値を推測しない。
- 参考: https://github.com/streamlink/streamlink/issues/4365 と https://gist.github.com/tor4kichi/c5475c8362ee897911e43c46f0918023 （旧資料のため現行サービスとの互換性は要確認）。
- r21: LIVEランキング画面を再構成し、各数値を個別表示。10件取得できる優先ソースを採用し、不足時は最多件数のソースに切り替える。取得失敗時は最大5分のWorkerキャッシュまたは閲覧中の前回結果を明示して表示する。公開統計の別名も補完する。
- r22: Kick公開ランキングを2取得先から並行取得し、同じチャンネルIDの配信時間を補完する。公式開始時刻がある場合は経過時間を計算し、公開経過時間は取得時点の表示とする。未取得の時間は推測しない。
